# Contributing

## Workflow

1. Create a focused branch.
2. Keep changes small and documented.
3. Run validation before opening a pull request.
4. Update docs when behavior changes.

## Validation

```bash
npm run lint
npm run build
```

Review:

- `docs/TESTING.md`
- `docs/DEPLOYMENT.md`
- `docs/SECURITY.md`

## Pull Requests

Every PR should include:

- summary of changes;
- validation performed;
- screenshots or notes for UI changes;
- migration notes for storage/import/export changes.
